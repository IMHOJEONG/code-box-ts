### 1. any

- 개발 단계에서 임시로 값을 지정해야 할 때

- 어떤 값을 받아올지 또는 넘겨줄지 정할 수 없을 때

- 값을 예측할 수 없을 때 암묵적으로 사용

### 2. unknown

- any 타입과 유사하게 모든 타입의 값이 할당될 수 있음

- any를 제외한 다른 타입으로 선언된 변수에는 unknown 타입 값을 할당할 수 없음

- any vs unknown

  - any

    - 어떤 타입이든 any 타입에 할당 가능

    - any 타입은 어떤 타입으로도 할당 가능 (단, never는 제외)

  - unknown

    - 어떤 타입이든 unknown 타입에 할당 가능

    - unknown 타입은 any 타입 외에 다른 타입으로 할당 불가능

- 함수를 unknown 타입 변수에 할당할 때는 컴파일러가 아무런 경고를 주지 않지만, 실행하면 에러 발생

- 함수 뿐만 아닌, 객체의 속성 접근, 클래스 생성자 호출을 통한 인스턴스 생성 등 객체 내부에 접근하는 모든 시도에서 에러가 발생

- unknown 타입은 어떤 타입이 할당되었는지 알 수 없음을 나타내기 때문에, unknown 타입으로 선언된 변수는 값을 가져오거나 내부 속성에 접근할 수 없음

- unknown 타입 = any 타입과 유사하지만, 타입 검사를 강제하고, 타입이 식별된 후에 사용할 수 있기 때문에, any보다 더욱 안전

### 3. void

- JS에선 함수에서 명시적인 반환문을 작성하지 않으면, 기본적으로 undefined가 반환됨

- TS에선, void 타입이 사용되는데 이것은 undefined가 아님

  - 함수가 아닌 값에 대해서는 대부분 무의미

### 4. never

- 값을 반환할 수 없는 타입

- 값을 반환하지 않는 것 vs 반환할 수 없는 것의 명확한 구분 필요

`JS에서 값을 반환할 수 없는 경우 2가지`

1. 에러를 던지는 경우

- JS에서는 런타임에 의도적으로 에러를 발생시키고 캐치할 수 있음

  - throw 키워드를 사용하면 에러를 발생시킬 수 있음

  - 값을 반환하는 것으로 간주하지 않음

  - 특정 함수가 실행 중 마지막에 에러를 던지는 작업을 수행한다면, 해당 함수의 반환타입은 never

2. 무한히 함수가 실행되는 경우

- 무한 루프는 결국 함수가 종료되지 않음을 의미하기 때문 - 값 반환 못해

- never 타입 = 모든 타입의 하위 타입

  - never 자신을 제외한 어떤 타입도 never에 할당될 수 없다는 것 의미

- TS에서는 조건부 타입을 결정할 때 특정 조건을 만족하지 않는 경우에, 엄격한 타입 검사 목적으로 never 타입을 명시적으로 사용하기도 함

### 5. Array

- TS에서는 일반적으로 배열의 크기까지 제한하지는 않지만, 정적 타입의 특성을 살려 명시적인 타입을 선언해 해당 타입의 원소를 관리하는 것을 강제함

- 배열 타입을 선언하는 방식은 다른 정적 언어에서의 선언 방식과 유사함

```ts
// 숫자에 해당하는 원소만 허용
const array: number[] = [1, 2, 3];
```

- 제네릭이라는 특수한 문법을 사용함

```ts
const array: Array<number> = [1, 2, 3];
```

- TS에서 배열 타입을 명시하는 것만으로, 배열의 길이까지는 제한할 수 없음

- 튜플은 배열 타입의 하위 타입으로, 기존 TS의 배열 기능에 길이제한까지 추가한 타입 시스템이라 볼 수 있음

- 튜플 = TS의 타입 시스템과 대괄호를 사용해서 선언할 수 있음

  - 대괄호 안에 타입 시스템을 기술하는 것이 배열 타입과 유일하게 다른 점

  - 대괄호 안에 선언하는 타입의 개수 = 튜플이 가질 수 있는 원소의 개수 (튜플은 배열의 특정 인덱스에 정해진 타입을 선언하는 것과 같음)

- TS에서의 배열과 튜플은 JS와 달리 제한적으로 쓰임

  - 배열은 사전에 허용하지 않은 타입이 서로 섞이는 것을 방지해 타입 안정성을 제공함

  - 튜플 = 길이까지 제한해 원소 개수와 타입을 보장

- 튜플 & 배열의 성질을 혼한해서 사용 가능

  - 스프레드 연산자를 사용해 특정 인덱스에서 요소를 명확한 타입으로 설정 후, 나머지 인덱스에선 배열처럼 동일한 자료형의 원소를 개수 제한 없이 받는 것

```ts
const httpStatusFromPaths: [number, string, ...string[]?];
```

### 6. enum

- 구조체를 만드는 타입 시스템
- TS에선 명명한 각 멤버의 값을 스스로 추론

- 각 멤버에 명시적으로 값을 할당할 수 있음

  - 모든 멤버에 일일이 값을 할당할 수도 있지만, 일부 멤버에 값을 직접 할당하지 않아도 TS는 누락된 멤버를 이전 멤버 값의 숫자를 기준으로 1씩 늘려가며 자동으로 할당함

- enum 타입 = 주로 문자열 상수를 생성하는 데 사용됨

  - 열거형은 그 자체로 변수 타입으로 지정 가능 = 이 때 열거형을 타입으로 가지는 변수는 해당 열거혀이 가지는 모든 멤버를 값으로 받을 수 있음 = 코드의 가독성 향상

- 주의점

  - 숫자로만 이루어져 있거나, TS가 자동으로 추론한 열거형은 안전하지 않은 결과가 올 수 있음

    - const enum으로 열거형을 선언하는 방법도 있음 - 역방향으로의 접근을 허용하지 않아 JS에서의 객체에 접근하는 것과 유사한 동작을 보장

    - const enum으로 열거형을 선언하더라도, 숫자 상수로 관리되는 열거형은 선언한 값 이외의 값을 할당하거나 접근할 때 이를 방지하지 못함
      - 문자열 상수 방식으로 선언한 열거형은 미리 선언하지 않은 멤버로 접근을 방지

  - 열거형은 타입 공간과 값 공간에서 모두 사용된다고 함

## 3.2 타입 조합

### 1. 교차 타입

- 여러가지 타입을 결합해 하나의 단일 타입 생성 가능

- A & B

### 2. 유니온 타입

- 타입 A 또는 타입 B 중 하나가 될 수 있는 타입

- A | B

- 교차, 유니온 타입은 여러 줄 걸쳐 표기 가능

```ts
type PromotionEventItem
| ProductItem
| CardItem;
```

### 3. 인덱스 시그니처

- 특정 타입의 속성 이름은 알 수 없지만, 속성값의 타입을 알고 있을 때 사용

- `[Key: K]: T`의 형태

  - 해당 타입의 속성 키는 모두 K 타입이어야 하고, 속성값은 모두 T 타입을 가져야 한다는 의미

- 다른 속성을 추가로 명시 가능 = 추가로 명시된 속성은 인덱스 시그니처에 포함되는 타입이어야 함

```ts
interface TEST {
  [key: string]: number | boolean;
  length: number; // OK
  isValid: boolean; // OK
  name: string; // ERROR!
}
```

### 4. 인덱스드 엑세스 타입

- 다른 타입의 특정 속성이 가지는 타입을 조회하기 위해 사용됨

- 인덱스에 사용되는 타입 또는 그 자체로 타입이기 때문 - 유니온 타입, keyof, 타입 별칭 등의 표현 사용 가능

```ts
type Example = {
  a: number;
  b: string;
  c: boolean;
};

type IndexedAccess = Example["a"];
type IndexedAccess2 = Example["a" | "b"];
// number | string
type IndexedAccess3 = Example[keyof Example];
// number | string | boolean

type ExAlias = "b" | "c";
type IndexedAccess4 = Example[ExAlias];
// string | boolean
```

- 배열의 요소 타입을 조회하기 위해 인덱스드 액세스 타입을 사용하는 경우도 존재
- 배열 타입의 모든 요소는 전부 동일한 타입을 가지며, 배열의 인덱스는 숫자

  - number로 인덱싱하여 배열 요소를 얻은 다음, typeof 연산자를 붙여주면 해당 배열 요소의 타입을 가져올 수 있음

```ts
const ProductTest = [
  {
    type: "product",
    name: "chicken",
  },
  {
    type: "product",
    name: "pizza",
  },
  {
    type: "card",
    name: "cheer-up",
  },
];

type ElementOf<T> = (typeof T)[number];

type PromotionItemType = ElementOf<PromotionList>;
```

### 5. 맵드 타입

- 다른 타입을 기반으로 한 타입을 선언할 때 사용하는 문법, 인덱스 시그니처 문법을 사용해서 반복적인 타입 선언을 효과적으로 줄일 수 있음

```ts
type Example = {
  a: number;
  b: string;
  c: boolean;
};

type Subset<T> = {
  [K in keyof T]?: T[K];
};

const aEx: Subset<Example> = { a: 3 };
const bEx: Subset<Example> = { b: "hello" };
const cEx: Subset<Example> = { a: 4, c: true };
```

- 맵드 타입에서 매핑할 때, readonly와 ?를 수식어로 적용 가능

  - 제거도 가능, 기존 타입에 존재하던 readonly나 ? 앞에 -를 붙여주면 해당 수식어를 제거한 타입 선언 가능

- 맵드 타입에선, as 키워드를 사용해 키를 재지정 가능

### 6. 템플릿 리터럴 타입

- JS의 템플릿 리터럴 문자열을 사용해, 문자열 리터럴 타입을 선언할 수 있는 문법

```ts
type Stage =
  | "init"
  | "select-image"
  | "edit-image"
  | "decorate-card"
  | "capture-image";

type StageName = `${Stage}-stage`;
// -stage를 붙여, 새로운 유니온 타입을 만들 수 있음
```
