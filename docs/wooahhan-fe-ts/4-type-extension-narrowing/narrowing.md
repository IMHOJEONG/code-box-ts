## 타입 좁히기 - 타입 가드 

- 변수 또는 표현식의 타입 범위를 더 작은 범위로 좁혀나가는 과정

- 타입 좁히기를 통해 더 정확하고 명시적인 타입 추론을 할 수 있게 됨 

    - 복잡한 타입을 작은 범위로 축소해 타입 안정성을 높일 수 있음 

### 1: 타입 가드에 따라 분기 처리하기 

- 조건문과 타입 가드를 활용해 변수나 표현식의 타입 범위를 좁혀, 다양한 상황에 따라 다른 동작을 수행하는 것 

- 타입 가드 = 런타임에 조건문을 사용해 타입을 검사하고, 타입 범위를 좁혀주는 기능을 의미 

- TS로 개발하다 보면, 여러 타입을 할당할 수 있는 스코프에서 특정 타입을 조건으로 만들어 분기 처리하고 싶을 때가 있음 

    - 여러 타입을 할당할 수 있다는 것 = 변수가 유니온 타입 또는 any 타입 등 여러 가지 타입을 받을 수 있다는 것을 의미 

        - 조건으로 검사하려는 타입보다 넓은 범위를 가짐 

- ex: 어떤 함수가 A | B 타입의 매개변수를 받는다고 가정 

    - 인자 타입이 A 또는 B일 때를 구분해서 로직을 처리하고 싶다면?

    - if문을 사용해서 처리?? 컴파일 시 타입 정보는 모두 제거되어 런타임에 존재하지 않기 때문, 타입을 사용하여 조건을 만들 수는 없음 

        - 즉, 컴파일해도 타입 정보가 사라지지 않는 방법을 써야 함 

- 특정 문맥 안에서 TS가 해당 변수를 타입 A로 추론하도록 유도하면서, 런타임에서도 유효한 방법이 필요함 => 타입 가드 

    - JS 연산자를 사용한 타입 가드, 사용자 정의 타입 가드로 구분 가능 

`JS 연산자를 사용한 타입 가드`

- typeof, instanceof, in과 같은 연산자를 사용해, 제어문으로 특정 타입 값을 가질 수 밖에 없는 상황을 유도해, 자연스럽게 타입을 좁히는 방식 

    - JS 연산자를 사용하는 이유는 런타임에 유효한 타입 가드를 만들기 위함 

    - 런타임에 유효하다 = TS 뿐 아니라, JS에서도 사용할 수 있는 문법이어야 함 

`사용자 정의 타입 가드`

- 사용자가 직접 어떤 타입으로 값을 좁힐지를 직접 지정하는 방식 

### 2: 원시 타입 추론 - typeof 연산자 활용 

- 원시 타입에 대해 추론 가능 

- typeof는 JS 타입 시스템만 대응 가능 

    - JS의 동작 방식으로 인해 null과 배열 타입 등이 object 타입으로 판별되는 등 복잡한 타입 검증 한계 존재 

- typeof 연산자는 주로 원시 타입을 좁히는 용도로만 사용할 것을 권장 

### 3: 인스턴스화된 객체 타입 판별 - instanceof 연산자 활용 

- 인스턴스화된 객체 타입을 판별하는 타입 가드로 instanceof 연산자 사용 가능 

- `A instanceof B` 

    - A : 타입을 검사할 대상 변수, B : 특정 객체의 생성자 

- instanceof: A의 프로토 타입 체인에 생성자 B가 존재하는지를 검사해서 존재한다면, true 아니면 false

- 주의! A의 프로토타입 속성 변화에 따라 instanceof 연산자의 결과가 달라질 수 있다는 점은 유의

### 4: 객체의 속성이 있는지 없는지에 따른 구분 - in 연산자 활용 

- in 연산자 = 객체에 속성이 있는지 확인 후 true 또는 false를 반환

    - in 연산자를 사용하면, 속성이 있는지 없는지에 따라 객체 타입 구분 가능 

- `A in B` = A 라는 속성이 B 객체에 존재하는지를 검사

    - 프로토타입 체인으로 접근할 수 있는 속성이면 전부 true를 반환 

- in 연산자는 B 객체 내부에 A 속성이 있는지 없는지를 검사하는 것이기 때문에, B 객체에 존재하는 A 속성에 undefined를 할당한다고 해서, false를 반환하는 것은 아님 

    - delete 연산자를 사용해 객체 내부에서 해당 속성을 제거해야만 false를 반환 

### 5: is 연산자로 사용자 정의 타입 가드 만들어 활용 

- 반환 타입이 타입 명제(type predicate)인 함수를 정의하여 사용 가능 

- `A is B` = A: 매개변수 이름, B: 타입

    - 참/거짓의 진릿값을 반환하면서, 반환 타입을 타입 명제로 지정하게 되면, 반환 값이 참일 때 A 매개변수의 타입을 B 타입으로 취급하게 됨 

- 타입명제 = 함수의 반환 타입에 대한 타입 가드를 수행하기 위해 사용되는 특별한 형태의 함수 

```ts
const isDestinationCode = (x: string): x is DestinationCode => destinationCodeList.includes(x)
// 함수의 반환 값을 boolean이 아닌 x is DestinationCode로 타이핑해, TS에게 이 함수가 사용되는 곳의 타입을 추론 시, 해당 조건을 타입 가드로 사용하도록 알려줌 
```

- TS에게 반환 값에 대한 타입 정보를 알려주고 싶을 때 is를 사용할 수 있음 

    - 반환 값의 타입을 `x is DestinationCode`로 알려줌으로써, TS는 if문 스코프의 str 타입을 DestinationCode로 추론 가능

## 4.3 타입 좁히기 - 식별할 수 있는 유니온 (Discriminated Unions)

- 태그된 유니온(Tagged Union)이라고도 함 


### 4.3.1: 에러 정의하기 

- 다양한 에러 객체가 있는 경우에, JS는 덕 타이핑 언어이기 때문에 별도의 타입 에러를 뱉지 않는 것을 확인 가능 

    - 타입 에러가 발생하지 않는다면, 앞으로의 개발 과정에서 의미를 알 수 없는 무수한 에러 객체가 생겨날 위험성이 커짐 


### 4.3.2: 식별할 수 있는 유니온 (Discriminated Unions)

- 그럼 에러 타입을 어떻게 구별?

- 각 타입이 비슷한 구조를 가지지만, 서로 호환되지 않도록 만들어주기 위해선 

    - 타입들이 서로 포함 관계를 가지지 않도록 정의해야 함 => 식별할 수 있는 유니온을 활용 하는 것 

`식별할 수 있는 유니온` = 타입 간의 구조 호환을 막기 위해 타입마다 구분할 수 있는 판별자를 달아주어 포함 관계를 제거하는 것 

### 4.3.3 식별할 수 있는 유니온의 판별자 선정 

- 주의! 식별할 수 있는 유니온의 판별자는 유닛 타입(unit type)으로 선언되어야 정상적으로 동작함 

- 유닛 타입 = 다른 타입으로 쪼개지지 않고 오직 하나의 정확한 값을 가지는 타입 의미 

    - null, undefined, 리터럴 타입을 비롯해 true, 1 등 정확한 값을 나타내는 타입이 해당    

    - 다양한 타입을 할당할 수 있는 void, string, number와 같은 타입은 유닛 타입으로 적용되지 않음 

## 4.4 Exhastiveness Checking - 정확한 타입 분기 유지하기 

- Exhastiveness Checking = 모든 케이스에 대해 철저하게 타입을 검사하는 것 

    - 타입 좁히기에 사용되는 패러다임 중 하나 

- 타입 가드 사용해 타입에 대한 분기 처리를 수행하면, 필요하다고 생각되는 부분만 분기 처리 -> 요구사항에 맞는 코드 작성 가능 

    - 때로는 모든 케이스에 대해 분기 처리를 해야만 유지보수 측면에서 안전하다고 생각되는 상황 생김
